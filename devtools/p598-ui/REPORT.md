# P5.98 · 人物卡角标按钮 + 人物详情页折叠/展开（真浏览器实测）

> 用户需求两条：
> 1.「人物卡片背景的调整按钮不要放在头像旁，放在卡片的某一个角落」
> 2.「人物详情页『视频 159』直接铺满很长一列 + 分页」—— 选**方案 b**：折叠 1–2 行 + 「查看全部 N 个视频」，
>   可收起、记住展开态，删掉页内分页。
>
> 跑法：`cd QTools-C && node devtools/p598-ui/run.mjs`（vite dev 现编真 SFC，人物数据走真实后端 127.0.0.1:8080）
> 被测数据：person 125「素人」= **视频 159 / 相册 2**（就是用户看到的那组数字）
> 结论：**PASS 60/60**，页面 0 console 错误；`vite build` 0 error；单测 19 个文件全 PASS（新增 48 条）。

## 1 按钮位置：选「对角方案」

| 方案 | 内容 | 取舍 |
|---|---|---|
| **A（本轮采用）** | ⛶ 调背景 → 卡片**右上角**；换 → 卡片**右下角** | 两钮相距 48px（对角），几何上不可能相叠；每个钮独占一个角，语义清楚 |
| B（未采用） | 两个都放右下、横向排列 | 最窄 280px 卡上「2×20px 钮 + 间距 + 角标沟」要吃掉约 50px 文字宽，3 chip 行会被压成 2 行、卡片变高 |

实现要点：
* 尺寸沿用 P5.93 的 **20px 圆钮**，贴边 `right: 7px / top: 7px`（⛶）、`right: 7px / bottom: 7px`（换），
  距**卡片外缘 8px**（含 1px 边框）→ 既在卡片内、又不贴死。
* 新增**右侧 24px 角标沟**：`.pw-card` 的 `padding: 10px 12px` → `10px 36px 10px 12px`（≤768 档 `9px 34px 9px 10px`）。
  于是文字区右边界恒在钮左边界左侧 ≥7px —— 这是「不压字」的**结构性**保证，不靠肉眼。
* 触发面从「头像 hover」放大到「整卡 hover / focus-within」：钮已经不在头像上了，再要求 hover 头像就找不到。
* `data-role`（bg-adjust-open / avatar-change）与 `@click.stop.prevent` 一字未改 → P5.88/P5.93 的实测脚本零改动通过。

## 2 详情页：折叠 → 展开 → 收起（方案 b，原页展开）

* **行数按视口宽度**：`window.innerWidth ≤ 768 → 1 行`，否则 2 行；相册区恒 1 行。
* **列数按浏览器实际排版**：`.pd-grid-*` 是 `auto-fill + minmax()`，页面读 `grid-template-columns` 的轨道数，
  折叠张数 = 列数 × 行数（**整行，绝不留半行**；不是 `max-height` 硬裁 —— 硬裁会切出半个卡片）。
* **请求**：折叠态首屏 `size=24`（够 2 行 × 最多 8 列）；展开时按总数补一次，后端 size 上限 200
  （实测 `size=500` 回 `size=200`）。二次请求只在「超宽屏一行超过 24 张」时发生。
* **展开 / 收起不改路由**（不跳视频库、不开新页）：展开 = 真渲染全部 159 张卡片。
* **持久化**：`sessionStorage['ms.person.detail.expand.<personId>.videos' | .albums'] = '1'`；收起时**删键**。
  刷新 / 返回仍在展开态；换人物各记一份。
* **页内「上一页 / 下一页」整组删除**（模板 + `.pd-pager` 样式 + pageCount / videoPage / albumPage 状态）。
* 标题右侧补一行小字「显示 12 / 159」，替代原来的页码。

## 7 已知限制

1. **触屏没有 hover**：两个角标钮沿用 P5.88/P5.93 的 `opacity: 0` + hover 显形（本轮只改位置，没改交互模型）。
   手机上点人物卡是直接进详情页，钮看不到 —— 改触屏入口需要另一套交互（长按菜单 / 常显），不在本轮范围。
2. **角标沟吃掉 24px 文字宽**：`.pw-card` 右侧 padding 12→36（≤768 档 10→34）。
   3 chip 行现在按更窄的宽度排版（`.pw-chips` 是 `flex-wrap: nowrap + overflow: hidden`，不会折行、不改卡片高度，
   只是可见 chip 少一点点）。卡片等高（104px）实测未变（p594 PASS 9/9）。
3. **展开是「一次全渲染」**：159 张卡片（375 档 80 行、页高 15665px）没有虚拟滚动；
   数据量再大（>200）后端 size 上限会截断，页面会显示「一次最多取 200 个，这里先显示前 N 个」，不静默截断。
4. **折叠态张数依赖量列**：首帧先按兜底列数渲染 2 张，量到真实列数后一帧内补到整行张数（Δ 一帧，肉眼不可见，
   与 P5.94 的「首帧不许跳」口径不冲突 —— 卡片高度恒定，变的是卡片个数）。
5. **相册区真实数据不出按钮**：2 本相册在 1 行里装得下，属于正确行为（不放空按钮）；机制用打桩 12 本验证。
