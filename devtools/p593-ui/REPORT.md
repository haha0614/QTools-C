# P5.93 · 背景调整弹层预览 = 应用后效果 + 卡片 hover 两钮不重叠

> 用户反馈两条：
> 1.「背景设置时的预览和应用后效果不同」——弹层里预览一个样，点保存后卡片另一个样。
> 2. 截图里卡右上角「换」与「⛶」两个小圆钮**叠在一起**。
>
> 跑法：`cd QTools-C && node devtools/p593-ui/run.mjs`（后端默认 127.0.0.1:8080，可用 `QT_BACKEND` 覆盖）
> 结论：**PASS 61/61**（本次实测 61 条断言全过，页面 0 console 错误）

---

## 1. 真因（先核实，两处都实测到）

### 1.1 预览 ≠ 应用：两套渲染管线

| | 卡片（P5.90 起） | 弹层预览（P5.88 起，直到本轮） |
|---|---|---|
| 谁渲染 | 服务端 `GET /api/media/person/{id}/card-bg`（Java） | 浏览器 CSS |
| 模糊 | `gaussianBlur(photo, w, h, blurPx)` 两遍（含 ×2.6 雾层） | `filter: blur(6px)`（CSS 近似，且**与出图尺寸脱钩**） |
| mask | 逐列 `stops()` 表（三张三停靠点曲线，按图片坐标 u 算） | `linear-gradient` + `mask-composite: intersect` |
| 柔光 / 垫底 | 拾色 `toneFill` + 椭圆 glow（rx=1.45w / ry=1.65h） | 只有 `--pw-tone` 底色 |
| 压缩 / 采样 | JPEG 0.82，tone 取自**原图** | 无压缩，tone 取自页面采样 |

两套实现不可能对齐 —— 这就是「预览一个样、应用后另一个样」的根因。
**改法 A（采用）**：弹层预览直接要**同一个端点**的图，参数就是保存后会写进卡片 URL 的那一份。

### 1.2 两钮「重叠」：≤768 档真的只剩 4px 缝

`.pw-avatar-wrap` 在 `≤768` 是 40px，而两个钮是 22px + `top/bottom: -4px`：

```
⛶ 占 [-4, 18]   换 占 [40-22+4, 40+4] = [22, 44]   → 缝 = 22 - 18 = 4px
```

22 + 22 + 8（上下各 4 的外溢）= 52 > 40，两条 22px 的圆钮在 40px 的头像盒里必然挤在一起（4px 缝在圆角 + 1px 描边下看起来就是「叠着」）。

## 2. 改法（前端三处 + 一个 P5.92 遗留真 bug）

### 2.1 弹层预览改用服务端同端点（WYSIWYG）

`QTools-C/src/views/media/PersonBgAdjustDialog.vue`

- 预览 `<img data-role="bg-adjust-card">` 指向 `/api/media/person/{id}/card-bg?w=<预览出图像素>&h=&s=&dx=&dy=&blur=&d=&bg=&v=`；
- **`s / dx / dy` 就是草稿值**（保存后写进 localStorage / 服务端的同一份），`d / bg / v` 与卡片同源；
- 服务端已保证「请求参数优先于库里已保存值」（`MediaPersonCardBgServiceImpl.param()`：`fromRequest != null ? fromRequest : saved`），实测确认；
- `w / h` 取预览盒像素，**构图与卡片逐像素一致**：服务端几何 `baseW = bgW·MAGNIFY/cw`、`tx = bgW·TARGET_X − imgW·cx + dx·bgW` 对盒子宽**线性**，同比例盒子只差一个缩放系数（实测 MAE ≤ 1.67/255，见第 3 节）；
- **`blur` 必须按出图宽等比换算**：服务端的 blur 是「输出像素」，预览盒（520）比卡片（332）宽，直接照抄会让预览的模糊轻一档 —— 新增纯函数 `personCardBg.previewBlur(committed, previewOutW, cardOutW)`，实测 `6 × 520/332 = 9`；
- 取图防抖 **160ms**，`new Image()` 预热装好才换 `src`（直接改 src 会先丢旧图闪一帧白）；
- 等图空窗期用一次仿射 **立即反馈**（纯函数 `personCardBg.transientTransform`）：
  `k = draft.scale/shown.scale`，`tx = (draft.dx − k·shown.dx)·boxW`（ty 同理），缩放原点取自动几何钉的 `(0.76·boxW, 0.5·boxH)`；
- 打开的第一个 100–200ms 里真图还在服务端渲染：先用**卡片自己那张图**（同构图、浏览器已解码）顶着，
  预览盒不会出现空白（断言 b0）；
- 端点 404/500 → `serverFailed`，预览退回 P5.88 三层 CSS（还能调，只是不再逐像素对准卡片）。

### 2.2 顺带修掉的一个真 bug：保存后卡片停在 240 宽低清图

P5.92 的两段式（先 240 宽占位 → 正式图）把「排正式图」只挂在 `measureCardBg`（**尺寸变化**触发）后面。
于是「保存一次调整」「拖完模糊滑块」「切主题」这些**只改参数不改尺寸**的路径一个都不会去取正式图 —— 卡片停在 240 宽的低清图上（还被拉伸到 333 CSS px），看起来比 520 宽的预览软一大截。
**这是「预览和应用后不一样」的第二个来源**，本轮实测抓到（`cardFullReadyExpr` 一开始按「naturalWidth === URL 里的 w」判，占位图自己就是 w=240，永远为真；改成按「.pw-bg 宽 × DPR」判之后立刻暴露）。

修法（`PersonsPage.vue`）：盯住「所有卡片正式图 URL 拼起来的那一串」，变了就 `scheduleCardBgFull(120)` 重排一次预载（只读 `cardBgPx` + 参数，不读 `cardBgFull`，不会自激）。

### 2.3 两钮不重叠

`PersonsPage.vue` CSS：两个钮 **22px → 20px**，贴边 **-4px → -3px**：

```
≤768（头像 40，卡片 padding 9/10）：⛶ 占 [-3, 17]  换 占 [23, 43] → 缝 6px ✓  贴边 9-3 = 6px ✓
≥1280（头像 56，卡片 padding 10/12）：缝 22px ✓  贴边 7px ✓
```

## 4. 调整过的旧断言（逐条）

1. **`p588-ui/run.mjs` B1「拖拽后预览图位移 ≈ 鼠标位移」→ 新增 SKIP**（`/预览图位移/`）。
   弹层预览不再是「靠 transform 移动的三层图」，位移这件事在服务端图里体现为**换一张新图**；
   「预览 = 应用后」改由 p593 的像素对比证明（B1 在老 harness 里已无意义）。
2. **`p588-ui/run.mjs` `DIALOG_PROBE` 兼容单图形态**：只找到 `[data-role=bg-adjust-card]` 时返回
   `{ imgs:[rect,rect,rect], serverImg:true, imgW:盒子宽 }`，让 A7/A9/A10/B3/C1 等旧几何断言
   走到 SKIP 分支而不是抛 `TypeError`（原来会因为 `.pba-img` 不存在而直接崩）。
3. **`p588-ui` / `p590-ui` 目标卡选取**：优先挑 `data-bg-adjust` 为空的卡。
   原因不是代码回归 —— 这台后端库里**站长存过全站调整**（person 125 `bgDy=-0.02`、另一人 `bgScale=1.39/bgDx=-0.03/bgDy=-0.12`），

5. **p588 `A3 按钮尺寸可用`** 的门槛是 `≥20px`，本轮按钮从 22px 收到 20px —— 仍满足，未改断言。

## 5. 已知限制

1. **模糊换算到滑块上限会被夹**：`previewBlur` 取整后夹到后端值域 0–20。滑块拉到 20 时预览需要 `20×520/332 ≈ 31`，被夹成 20 → 这一档预览的相对模糊比卡片轻 ~1.57×。
   实测（`person/125`，卡片 `w=332&blur=20` vs 预览 `w=520&blur=20`，预览下采样到 332×102 比）：**MAE = 2.19/255，max 32** —— 仍远低于 8/255 阈值（这一档图本身已经很糊，像素差被压缩），但方向上是「预览略清晰」。
   要彻底消除得让后端 blur 走「相对宽度」参数（接口改动），本轮没做。0–12 档（常用区间）不受影响：`12×520/332 = 19` 仍在值域内，实测 MAE 1.45/255。
2. **预览盒比卡片大**（520 vs 332），所以预览永远是「卡片的等比放大」；显示器 DPR=2 时预览出图 1040 宽，仍在上限 1200 内，不会降级。
3. **拖动期只有一次仿射近似**（垫底色 / 柔光不参与变换），真图到位即归位；160ms 内的过渡是近似的，不是逐像素。
4. **服务端预览与卡片共用同一份 cache**（内容寻址）：预览尺寸的缓存文件也会落在 `card-bg` 缓存目录里，30 天 TTL 后由既有清理逻辑统一回收（尺寸数量有限：预览盒宽固定 ≈ 520/312，不会无限增长）。
5. **不是站长时**保存仍只写 localStorage，服务端已有调整会压过它（P5.89 设计如此，本轮未动）。实测 harness 因此只挑「无生效调整」的卡。
6. **harness 偶发 CDP 卡顿**：headless Chrome 渲染进程忙（解码 / 拾色采样大图）时单次 `Runtime.evaluate` 可能挂住，
   `evaluate()` 已做「25s 超时 + 重试一次」；极端情况下两次都超时会让整轮中断（重跑即可，非产品问题）。
