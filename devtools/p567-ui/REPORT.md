# P5.67 —— 人物卡片「头像铺满背景」实现与实测报告

需求原话：「用户端人物卡片能不能设计一个背景，背景图像也是头像，只不过展示面积比头像大」。
范围：只改 `QTools-C/src/views/media/PersonsPage.vue`（+ 新增本轮实测脚本 `devtools/p567-ui/run.mjs`），未动管理端、未跑 git。

---

## 1. 实现方式（blur vs scale：两者都用，各管一件事）

卡片内三层（`.pw-card` 加 `position: relative; overflow: hidden; isolation: isolate`）：

| 层 | 元素 | z-index | 作用 |
|---|---|---|---|
| 底 | `.pw-bg > img`（**与头像同一个 URL**） | 0 | `object-fit: cover` + `object-position: center 25%` + `filter: blur(6px) saturate(1.1) brightness(.9)`（P5.69；P5.67 原为 blur(12px)）+ 层上 `opacity: .7`（P5.69） |
| 中 | `.pw-mask` | 1 | 水平渐变遮罩（亮/暗两套），`pointer-events: none` |
| 上 | `.pw-avatar-wrap` / `.pw-body` | 2 | 小头像（56/40px）、「换」按钮、名字 / 数量 / chip / 最近更新 |

- **为什么用 `<img>` 而不是 `background-image`**：需求 4 要求「`img.onerror` 或 CSS 加载失败 → 移除背景层（静默）」。
  `background-image` 拿不到 onerror，只有 `<img @error>` 可以；同时 `<img>` 才能吃到 `loading="lazy"`。
  URL 仍是**同一条**字符串（`avatarSrcOf(card)`），所以「同一个 URL」这条没变。
- **模糊边缘发白怎么避免**：`blur(6px)` 会从图片边缘往里渗透明像素。这里不用 `scale(1.15)` 硬撑，
  而是把 img 四周**外扩 9px**（`inset: -9px; width/height: calc(100% + 18px)`，= 模糊半径的 1.5 倍；P5.67 原为 16px），模糊只吃图片自身像素。
  好处是 hover 的 `transform: scale(1.03)` 就是需求里那个字面值（scale 留给交互，不外扩兼职）。
- **hover**：`.pw-card:hover .pw-bg img { transform: scale(1.03); filter: … brightness(1) }`，`transition: 120ms`。
  「换」按钮在 `.pw-avatar-wrap`（z-index 2）里，永远压在背景之上；实测 `elementFromPoint` 命中按钮本身、opacity=1。
- **@supports 回退**：`@supports not (filter: blur(4px))` → 去掉模糊，同时把遮罩加厚（亮 .96/.93/.84，暗 .95/.92/.84），
  退化成「清晰图 + 半透明遮罩」，文字对比度仍 ≥4.5:1。
- **动效偏好**：`prefers-reduced-motion: reduce` 时取消 hover 放大与过渡。
- 圆角跟随卡片（`.pw-bg`/`.pw-mask` 都 `border-radius: inherit`），背景不溢出（`.pw-card { overflow: hidden }`）。

## 2. 遮罩取值与对比度（推导 + 实测）

文字色：亮 `--fg` = #303133，暗 `--fg` = #e5eaf3（都是 `--qt-text-primary` 经 mediaTheme 映射）。

亮色遮罩  `linear-gradient(90deg, rgba(255,255,255,.93) 0%, .88 50%, .62 100%)`
暗色遮罩  `linear-gradient(90deg, rgba(18,18,18,.90) 0%, .82 46%, .66 100%)`

**为什么不是需求草稿里的 .55**：最坏情况推导 —— 亮色下整片底色可能是近黑（`255×α`），
`.55` 时合成像素 140，与 #303133 只有 **3.67:1**（长姓名被省略号截断后会一直延伸到卡片右边）；
`.62` 时 158 → 4.47:1，实测取 .62 且文字色提到 `--fg` 后是 5.33:1（见下表）。
暗色最坏是整片近白（`18α + 255(1-α)`），`.66` 时合成 99.7 → 解析 4.9:1，实测 6.27:1。

**为达成 ≥4.5:1 改动的两处旧样式（必须说明）**：

1. `.pw-name` 之前**没有**自己的 color，继承 `.media-scope a { color: var(--accent) }`（#409eff）——
   压在纯白卡片上只有 **2.78:1**，压在照片背景上实测 **1.25:1**（这正是第一轮实测的 FAIL）。
   现在 `.pw-name { color: var(--fg) }`：亮色纯底 12.6:1、压在照片上最差 5.33:1。姓名是卡片主信息不是行内链接。
2. `.pw-card.has-bg` 上的 `.pw-counts` / `.pw-recent` / `.pw-alias` 从 `--fg-dim` 提到 `--fg`，
   并把 `.pw-recent` 的 `opacity: .85` 取消（压在照片上会再掉一档）。
   `--fg-dim`（#6a6c70）压在照片上最坏只有 **2.5–3.9:1**，光靠加厚遮罩要到 α≥.93 才够，那背景就看不见了。
   没有背景层的卡片（首字占位 / 无头像）保持原样。

**实测（像素采样，PNG 自解 + WCAG 公式；样本 = 文字行盒上下各 2px 的整行像素，取最差）**：

| 视口 | 主题 | 姓名最差 | 数量行最差 | 采样底色 | 样本数 |
|---|---|---|---|---|---|
| 1600×1000 | 亮 | **5.34:1** | 5.34:1 | rgb(166,166,164) | 242 |
| 1600×1000 | 暗 | **6.27:1** | 6.29:1 | rgb(85,84,82) | 242 |
| 1200×900 | 亮 | **5.34:1** | 5.40:1 | rgb(166,166,164) | 224 |
| 1200×900 | 暗 | **6.29:1** | 6.29:1 | rgb(83,84,85) | 224 |
| 375×812 | 亮 | **5.33:1** | 5.33:1 | rgb(165,166,164) | 258 |
| 375×812 | 暗 | **8.17:1** | 8.75:1 | rgb(67,67,70) | 258 |

全部 ≥4.5:1，最低 5.33:1（375 亮色）。采样脚本见 run.mjs 的 `bgSamples()`：与文字色距离 <40 的像素丢弃，
避免把自己的字形当成底色（本次 6 档 dropped 全为 0）。

## 4. 失败回退 / 缺失

| 情况 | 行为 | 实测 |
|---|---|---|
| 头像是首字占位（kind=initial，`avatarSrcOf` 返回空串） | 不渲染 `.pw-bg` / `.pw-mask` | G 组：4 项断言 PASS |
| 头像加载失败（`avatarFailed`） | 背景层同时消失，头像退回首字 | H 组：3 项 PASS |
| 背景图自己 `@error`（`bgFailed`） | 只摘背景层，不动头像 | 代码路径 + H 组同 URL 场景覆盖 |
| 取帧档（kind=frame） | 沿用既有 IntersectionObserver 懒加载，进视口前背景也是空的 | p560 G 组 12 项 PASS |
| 浏览器不支持 filter | `@supports not` → 无模糊 + 加厚遮罩 | 构建产物内含该分支（未在旧引擎实测） |

## 5. 网络层证据（不额外下载）

做法：vite 的 `VITE_PROXY_TARGET` 指向本进程里的**计数代理**（再转发到 :8080），
「后端到底收到几次 thumb 请求」是可数的原始事实；每次跑前 `Network.clearBrowserCache`，冷缓存下计数才干净。

```
[1600/light] DOM 图元素 26 个（13 头像 + 13 背景）/ 后端 thumb 请求 13 次 / 去重 URL 13 个
  样例（素人）
    avatar src = /api/media/thumb/p/a159/0000?crop=0.2111,0.1875,0.6000,0.3375
    bg src     = /api/media/thumb/p/a159/0000?crop=0.2111,0.1875,0.6000,0.3375
    相等       = true
```

- 每个头像 URL 后端只收到 **1 次**请求（重复：无）。
- `performance.getEntriesByType('resource')` 里每个 thumb URL 也只有一条。
- 结论：背景层没有增加任何下载；26 个 img 元素 → 13 次请求。

## 7. 已知限制

1. **亮色主题的人像偏淡**：为了数量行 / 长姓名在卡片右端仍有 4.5:1，亮色遮罩最薄只能到 .62，
   人像呈「柔和照片水洗」而不是暗色那种清晰人像。要更强的人像就得放宽对比度目标（例如只要求 ≥3:1 的大字口径）。
2. **每张卡的 blur 是一个合成层**：13 张卡 ≈ 13 个 12px 高斯模糊层，滚动时由 GPU 承担。
   本机 1600×1000 三档实测无掉帧观测手段（未测 FPS）；如后续墙上百张卡，可改为
   「hover 才开 blur / 只在小屏开」的降级。
3. **背景是装饰**：`.pw-bg` / `.pw-mask` 都 `aria-hidden="true"` + `pointer-events: none`，
   不影响读屏与点击；但也就没有「点击背景换图」这类交互。
4. **@supports 回退未在真旧引擎验证**：只保证分支存在且取值按最坏情况算过。
5. 背景与头像共用同一 URL 意味着**换头像 = 换背景**（这正是需求要的），保存后两层一起更新。

## 8. P5.69（用户反馈「模糊度过高，淡一点」）收档

用户原话：「人物卡片背景的模糊度是不是过高了，淡一点」——P5.67 的 `blur(12px)` 把整张脸糊成一团色块，
视觉上压过了卡片主体。两个方向一起收，只动 `PersonsPage.vue` 里 `.pw-bg` / `.pw-bg img` 两条规则，**遮罩取值未动**：

| 项 | P5.67 | P5.69（现役） |
|---|---|---|
| 模糊 | `filter: blur(12px) saturate(1.1) brightness(.9)` | `filter: blur(6px) saturate(1.1) brightness(.9)` |
| 外扩 | `inset: -16px`；`calc(100% + 32px)` | `inset: -9px`；`calc(100% + 18px)`（= 6px × 1.5） |
| 整体浓度 | —（无） | `.pw-bg { opacity: .7 }` |
| 遮罩 | 亮 .93/.88/.62，暗 .90/.82/.66 | **不变** |
| hover | `scale(1.03)` + `blur(12px) … brightness(1)`，120ms | `scale(1.03)` + `blur(6px) … brightness(1)`，120ms |

**实测（`out/p569/run.log`，同一套像素采样口径；`120 / 120 PASS`）**：

| 视口 | 主题 | 姓名最差（新 / 旧） | 数量行最差（新 / 旧） |
|---|---|---|---|
| 1600×1000 | 亮 | **7.15:1** / 5.34:1 | **7.15:1** / 5.34:1 |
| 1600×1000 | 暗 | **8.08:1** / 6.27:1 | **8.17:1** / 6.29:1 |
| 1200×900 | 亮 | **7.08:1** / 5.34:1 | **7.15:1** / 5.40:1 |
| 1200×900 | 暗 | **8.08:1** / 6.29:1 | **8.18:1** / 6.29:1 |
| 375×812 | 亮 | **7.08:1** / 5.33:1 | **7.08:1** / 5.33:1 |
| 375×812 | 暗 | **10.45:1** / 8.17:1 | **10.11:1** / 8.75:1 |

六档全部 ≥4.5:1，最低 7.08:1（亮色）。对比度**反而上升**是设计使然：`.pw-bg` 降到 .7 后，
背景是「照片 × .7 + 卡片底色 `--bg-2` × .3」，亮色往近白收、暗色往近黑收，两侧都对文字是加分项，
所以这一轮不需要加厚遮罩补对比度（加厚会把「看得见人像」再压回去）。

**视觉结论（新旧 3× 放大对照在 `devtools/p569-compare/`）**：

- 旧版：卡片右侧是一团连续的灰糊影，边界糊到看不出画面结构（用户说的「模糊度过高」）。
- 新版：同样的位置变成很淡的一层照片水洗，**发色 / 肩线 / 明暗块面可辨**，五官不可辨——这正是「淡一点」要的度；
  文字区（左侧头像 + 名字 + 数量 + chip + 最近更新）干净，没有任何墨迹旁的深色斑。
- 暗色保留的人像结构比亮色多（遮罩右侧 .66 + 深底），亮色最淡（遮罩右侧 .62 + 近白底）。

**断言同步**：`run.mjs` 只改了「背景样式断言」这一处口径（`/blur\(12px\)/` → `/blur\(6px\)/`，说明串同步），
其余 119 条一字未改。`@supports not (filter: blur(4px))` 回退（`filter:none` + 更厚遮罩）与
`prefers-reduced-motion: reduce` 分支都保留，回退分支额外吃到 `.pw-bg` 的 .7，只会更安全。

**已知限制（更新 §7-1）**：亮色下人像现在更接近「极淡照片水洗」，轮廓可辨、五官不可辨；
再淡一档（`.pw-bg` opacity ≤ .55 或遮罩右端 ≥ .72）就只剩色温变化、看不出是人像了。
