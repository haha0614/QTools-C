## 1. 做了什么

### P5.76 —— 定位方式换了（根因）

| | P5.67–P5.75 | P5.76 |
|---|---|---|
| 定位 | `object-fit: cover` 铺满整卡（竖图被裁成一条横带，脸只剩中段） | `height:100%` + `width:32%` + `right:0` + `contain`（按高贴合、右对齐、不裁） |
| 左侧过渡 | `.pw-mask` 整卡分区遮罩（亮 .94/.13、暗 .92/.18）+ 文字块半透明垫底 + 整层 opacity .7 | 图片自己的 `mask-image` 渐隐 + 文字 text-shadow（**没有任何垫底**） |
| 外扩 | `inset: -1.5 × 半径`、尺寸 `卡片 + 3 × 半径` | 删除（图片不再被裁，没有「被裁的边」要兜） |

最终 CSS（`PersonsPage.vue`）：

```css
.pw-bg img {
  position: absolute; top: 0; right: 0;
  height: 100%; width: 32%;            /* 固定盒：图源宽高比 0.67–1.77 浮动，盒宽跟着变会让 mask 停靠点乱跑 */
  object-fit: contain; object-position: right center;
  filter: blur(var(--pw-bg-blur, 6px)) saturate(1.1) brightness(0.9);
  mask-image: linear-gradient(to right,
      transparent 0%, rgba(0,0,0,.12) 30%, rgba(0,0,0,.24) 56%, #000 74%);
}
.pw-card.has-bg .pw-body { padding-right: calc(14% - 8px); }   /* 文字列护栏，不是垫底 */
```

渐隐公式（按**图片自身宽度**取百分比，所以任何图源比例下都是「左 56% 淡、右 26% 实」）：

`alpha(f) = 0.12·(f/0.30)` (f ≤ 30%) ；`0.12 + 0.12·(f−0.30)/0.26` (30% < f ≤ 56%) ；
`0.24 + 0.76·(f−0.56)/0.18` (56% < f ≤ 74%) ；`1` (f > 74%)

护栏的由来：`.pw-body` 的 `padding-right` = 图片盒宽的 44% + 卡片 padding 的补偿 ⇒ **文字行盒右缘
一定落在图片宽度的 ≤56%**，也就是 alpha ≤.24 的那一段（A17 断言像素级复核）。

### P5.77 —— 整卡底色 = 从头像拾色（新增 `src/views/media/personTone.js`）

* 采样：`new Image()` + `canvas.drawImage(img, 0, 0, 8, 8)` → 64 像素均值（`alpha < 8` 的透明像素跳过）。
  8×8 而不是 1×1：1×1 会把极端黑/白一并平均进去，8×8 再过滤透明更接近「印象色」，而成本一样是 <1ms。
* 缓存键：`${avatar.kind}:${avatar.ref || avatar.url}`（**不是**卡片 id —— 详情请求晚到会把头像从
  「相册封面」升级成「显式头像 / 视频帧」，键必须跟着图走，否则会出现「旧图的颜色刷在新图上」；
  本轮实测踩过：一张卡的拾色与它现在显示的图差了一倍）。
* 落地色 `toneFill(tone, themeBg, theme)`：**不直接刷采样色**，而是按目标亮度做二分混合（18 次），
  在「亮度护栏内」取最大的采样色占比：亮色主题混合后亮度 ≥ .52、暗色主题 ≤ .045
  （给文字区下面那层 alpha ≤.24 的照片淡出段留预算）。护栏是实测调出来的，见第 4 节。
* 页面侧：`requestIdleCallback`（无则 `setTimeout 0`）+ 并发 2 逐张算，结果写 `--pw-tone` 与
  `has-tone`；主题切换用 `MutationObserver` 监听 `html.dark` 重算落地色（不重新采样）。
* localStorage：`ms.cardTone.v1`，最多 200 条（超出丢最旧），写失败静默。

## 7. 已知限制

1. **1200 档最长的数量行可能少 1–5px**：卡片 318px 宽时文字列可用 242 − 护栏（≈32）≈ 210px，
   而「159 部视频 · 2 本相册 · 118 张照片」实测需要 197px —— 目前全部放得下；以后若文案更长，
   会先在最窄的列上出现省略号（护栏不能让，否则对比度掉到 3.6:1）。
2. **超宽图源（1.77:1）会缩进盒内**（`contain` 保完整，上下留白），不是按高填满 —— 13 张卡里只有 1 张
   是这种比例。同理，**竖裁图（0.67:1）**按高贴合但更窄，靠右对齐。
3. **暗色主题的色调是「压暗后的版本」**（亮度上限 .045）：视觉上只是比底色亮一点点，比亮色主题含蓄。
   这是对比度预算的硬约束，不是偷懒。
4. **采样依赖同源**：跨域图源（未来若换 CDN）canvas 会抛 SecurityError，`sampleTone` resolve(null) →
   卡片退回 `--bg-2`，无接缝消失但不报错。
5. **模糊 6 档下（默认）人像是一团柔和的色斑**：这是用户自己把滑块放在 6px 的结果，0 档才是清晰人像。
6. 拾色结果**不随图片内容变化失效**（键只跟 URL / crop 走）；后端若原地替换同一 URL 的图，需要清
   `ms.cardTone.v1`（或升版本号）。

# P5.78 —— 背景改用「整张原图」，裁剪切中心落在卡片 76%

## 之前为什么错
P5.76 拿 `avatarUrl` 当背景 —— 那是后端按 `crop` **裁好的方块**，等于把「我选中的那一块」当整图，
所以卡片左侧只能靠拾色填。用户要的是：**整张原图**铺进卡片，让「裁成头像的那块」的位置落在右侧。

## 现在的实现（`src/views/media/personBgImage.js`，纯几何，单测 29 条）
```
原图 URL   = avatarUrl 去掉 crop 参数（photo: /api/media/thumb/p/<album>/<seq>；frame: …?t=&w=）
crop 中心  = parseCrop(ref) 或 parseCrop(url) → x + w/2（无 crop = 0.5）
scale      = 卡片内高 / 原图自然高
imgW       = 原图自然宽 × scale
tx         = 卡片宽 × 0.76 − imgW × cropX      ← 把裁剪中心推到卡片 76%
约束       右侧不留空（imgW + tx ≥ 卡片宽）；左侧允许露拾色底（目标优先于「铺满」）
```
CSS：`.pw-bg img { left:0; height:100%; width: var(--pw-img-w); transform: translateX(var(--pw-img-tx)) }`，
`ResizeObserver`（wall）+ `img @load` 触发重算，结果按 `src + 卡片尺寸` 记忆；
左下 40px `mask-image` 渐隐 + 卡片 `::before` 方向性遮罩（落地色 92% → 62% 处开始淡出），文字区对比度靠它。

## 已知限制（重要）
1. **超竖图（400×712）按高缩放后只有 57px 宽** —— 右侧留白不允许，所以只能右对齐到 91%，够不到 76%。
   若用户希望这类图也铺满卡片，需要改成「按卡片**宽**缩放（会裁上下）」或「加最小缩放倍数」——这是产品取舍，未擅自改。
2. 原图比卡片窄时右侧会被卡片裁掉（`overflow:hidden`），属于「铺满右侧」的预期行为。
3. 左侧 92% 遮罩下原图内容只透出约 8%，观感是「带色调的照片淡影」；再淡就会跌破 4.5:1（实测 0.84 → 4.16）。
4. 拾色仍只按头像图（同 URL 规则）采样，键为 `kind:ref`；换头像自动失效。
