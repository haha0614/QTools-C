## 3. 角标沟：为什么不是「完全恢复 12px」

实测（同一张卡，只改 `padding-right` 再量）：

| padding-right | 姓名行宽 | ⛶ 与姓名 / 正文 | 说明 |
|---|---|---|---|
| 12px（完全恢复） | 243.25 | **相交**（横向 11px、纵向 13px） | 20px 钮左缘恒在「卡片外缘 − 24px」，压住姓名尾部 |
| **24px（本轮）** | **231.25** | **0 相交**（缝 1px） | = 原 12px + **12px 沟** |
| 36px（P5.98） | 219.25 | 0 相交（缝 13px） | 为**两个**角钮留的通道，现在只剩一个 |

几何下界：`padding-right ≥ 钮宽 20 + 贴边 3 = 23px`（另加 1px 边框）；取 24px。
「20px 钮 + 4px 贴角 + 0 相交 + padding 完全恢复」四者不可兼得 —— 本轮保前三条，文字区相对 P5.98 **回收 12px**（窄屏 34 → 24）。

## 4. 底色 / 不透明度：取舍与实测（协调者拍了最终口径）

静止不透明度会把钮底与字色**一起**往卡片图上拉，所以「主题白底 + 灰字」在亮图卡上压不住字形。逐卡实测（同样取样方法）：

| 方案 | 亮 ⛶ 最小 | 亮 换 最小 | 暗 ⛶ / 换 最小 |
|---|---|---|---|
| A 原样（`--bg-2` 白底 + `--fg-dim` 灰字，静止 0.45） | 1.74 | 1.96 | 1.97 / 2.38 |
| B 只把字色换 `--fg`（静止 0.45） | 1.74 | 2.41 | 3.06 / 3.43 |
| C `rgba(0,0,0,.35)` 半透明底（简报里提的「极淡底色」档） | 2.11 | **1.60** | — |
| D 不透明 `#16181c` + `#f2f3f5`（静止 0.45） | 3.67 | 3.14 | 3.67 / 4.12 |
| **E `rgba(22,24,28,.92)` + `#f2f3f5`（静止 0.55）＝最终采用** | **4.34** | **3.91** | **4.34 / 5.65** |

半透明底反而更差：卡片图会透过底（「换」压在头像上，亮脸把盘面提亮）。
协调者口径：底色再降一档存在感（`.92` 近乎不透明但留 8% 透）、静止不透明度提到 0.55 —— 实测掉不到 3:1 以下（最小 3.91），故采用，未回落到 0.45 + 全不透明。
复跑方式：`node devtools/p601-ui/contrast-experiments.mjs`（脚本里 `VARIANTS` 即上表各档，逐档现改 CSS 再取像素）。

## 8. 已知限制 / 环境备注

1. **所有 harness 都以访客身份跑，前提是主库对访客可见**：`GET /api/media/persons` 返回 `[]`
   （`person/<id>/card-bg` 同时 404）时，四套旧 harness 都会在 `openWall` 处报「人物墙没渲染出来」。
   本轮期间这台机器上有别的进程来回翻 `media_root.guest_visible`（`sys-user.log` 里 admin 登录不断），
   协调者已把值改回 1。以后复跑前先 `curl /api/media/persons` 确认非空。
2. **冷启动离线占位**：见 §6 第 8 条 —— vite 首次编译时的整页 reload 会掐断 3s 的后端探测，页面显示
   「后端服务暂不可用」，与本次改动无关（`useBackendHealth` 连续 2 次失败即判离线）。
   p590 已加「点重试按钮 → 整页重载」的恢复步骤（人类操作等价物），加上之后才能跑到 26/30；
   p601 / p593 / p594 / p598 这几轮没有触发该问题。
3. 「换」与头像盒的角落重叠是设计要求（骑在头像圆右下角），任何「两钮与头像 0 相交」的断言都需要豁免。
4. 两钮底色（近黑、近乎不透明）+ 静止 0.55 是「低调 + 看得清」两条要求共同逼出来的（§4 有实测对比）；
   若用户不喜欢这个观感，需要放宽其中一条（降存在感就得接受字形 <3:1，或降不透明度就得接受浅底看不清）。
5. ⛶ 距卡片外缘 4px，贴着 10px 圆角；若以后把卡片圆角调到 ≥12px，需要复查钮是否被圆角切到。
