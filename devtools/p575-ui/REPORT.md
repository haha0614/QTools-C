## 1. 遮罩新公式

几何（`.pw-mask` 的 `linear-gradient(90deg, …)`，左→右）：

| 区间 | 作用 | 亮色 alpha | 暗色 alpha |
| --- | --- | --- | --- |
| 0–45% | 左区（头像 + 姓名 + 数量 + chips） | `--pw-mask-l1` = **.94**（恒定） | `--pw-mask-d1` = **.92**（恒定） |
| 45–62% | 过渡带（线性） | 渐变自插值 | 渐变自插值 |
| 62–100% | 右区（纯图片） | `--pw-mask-l2` = **.10 → .20** | `--pw-mask-d2` = **.15 → .25** |

右区公式（`t = n / 20`）：

```
right(n) = right0 + (right20 − right0) × t
亮色 light: right0 = 0.10, right20 = 0.20   →  right(n) = 0.10 + 0.05·n/10
暗色 dark : right0 = 0.15, right20 = 0.25   →  right(n) = 0.15 + 0.05·n/10
左区：不随半径变化（文字对比度不允许因拖动而变）
```

第三层（`bgOpacity`，本轮新增）：`n ≥ 6` → `.70`；`n < 6` → `1.00 + (.70−1.00)·n/6`。
理由：`.pw-bg` 的 `.7` 意味着「只留 70% 照片、30% 是卡片底色」——只松遮罩不松它，0 档依旧是洗白的。

## 3. 文字可读性兜底：为什么选「垫底」而不是只加 text-shadow

* 采样口径（p567/p572/p575 同一套）：取文字**行盒上下各 2px**（行距里、不压墨迹）的整行像素，取最坏一个。
  这个位置在 line-box 之外，`text-shadow: 0 1px 2px` 的光晕到不了（汉字行高 1.5 倍，行盒外 2px 已是行距），
  所以**只靠 text-shadow 兜不住实测**。
* 因此垫底是主手段：`.pw-card.has-bg .pw-body` 加
  `background: color-mix(in srgb, var(--bg-2) 65%, transparent)`（不支持 color-mix 时先吃 `rgba(255,255,255,.65)` /
  `rgba(20,20,20,.65)` 一行），`border-radius: 8px`，`padding: 4px 6px` + `margin: -4px -6px`（文字位置与卡片高度都不变），
  `flex: 0 1 auto; max-width: 100%` 让它按**最宽的一行收缩** —— 右侧照片区一点不遮。
* text-shadow 仍保留（`0 1px 2px` 亮白 / 暗黑），只用于垫底右缘与照片交界处的边缘锐利度。
* 65% 是实测定的：78% 最差 8.19:1（余量浪费），65% 最差 5.94:1 仍然安全，同时照片在文字后面多透出 13 个百分点。

## 5. 0 档右侧照片到底清不清楚（三档截图 + A/B 量化）

右侧「纯图片区」定义为 `max(62%, 垫底右缘 + 4px) … 卡右 - 3`（把文字垫底排除掉），逐像素统计：

| 主题 | 档位 | 局部细节 detail | 明暗跨度 sd | 彩色 chroma | 偏离卡片底色 distBg | 均值 RGB |
| --- | --- | --- | --- | --- | --- | --- |
| 亮 | 0px | 0.006 | 0.122 | 6.09 | **255.88** | 108,109,104 |
| 亮 | 6px | 0.005 | 0.130 | 3.62 | 185.56 | 149,149,146 |
| 亮 | 20px | 0.004 | 0.078 | 2.27 | 189.93 | 146,146,144 |
| 亮 | **旧 0px（P5.72：右 .78 + opacity .7）** | 0.003 | 0.059 | 1.05 | **43.96** | 230,230,229 |
| 暗 | 0px | 0.004 | 0.080 | 5.77 | **91.32** | 81,82,77 |
| 暗 | 20px | 0.001 | 0.016 | 1.98 | 23.99 | 41,41,40 |
| 暗 | **旧 0px** | 0.000 | 0.003 | 0.66 | **8.71** | 26,26,25 |

* `distBg` 在 0 档是旧取值的 **5.8 倍（亮）/ 10.5 倍（暗）**，`sd` 是 **2.1 倍 / 26 倍** → 「一片灰白」确实变成了照片。
* A/B 的做法：滑块停在 0，现场把 `--pw-mask-l2/d2` 改回 .78/.86、`--pw-bg-opacity` 改回 .7（= P5.72 的 0 档画面），
  同一张卡同一位置再量一次，并另存截图 `out/after/p575-card-0-{light,dark}-OLD-P572.png`。
* **截图目视结论（`out/after/`）**：
  * `p575-card-0-light.png` / `p575-card-0-dark.png`：0 档右侧能看出照片本体（亮色：发丝与背景层次；暗色：发色、衣物、背景环境都有），
    文字压在 65% 垫底上清晰；对照 `…-OLD-P572.png` 是整片灰白。
  * `p575-blur-0-dark.png`（整墙暗色）：多张卡右侧的人像可直接辨认（如「是小逗逗」整张脸、发饰，「念念」的红色画面，「梨霜儿」的暖色背景）。
  * 0/6/20 三档的差别现在集中在**清晰度**而不是**亮度**：0 档是清晰照片，20 档是隐约氛围。
  * 左半幅仍是压暗区（.94/.92）：这是设计（头像 + 文字都在左边），0 档不会把整张卡恢复成照片墙。

## 7. 已知限制

1. **照片可见区取决于文字宽度**：垫底按最宽一行收缩，长文案卡（如「159 部视频 · 2 本相册 · 118 张照片」）垫底占到卡宽 ~79%，
   右侧纯图片区只剩 ~20%；短文案卡能到 ~35%。想再露照片只能牺牲文字信息（截断数量行）或改成 P5.76 那种「图片右对齐」的定位。
2. **左半幅（0–45%）仍是压暗区**：这是本任务的要求（护文字），代价是 0 档也看不到左半幅的照片内容。
3. **人像主体多落在卡片中偏左**（`object-position: center 25%` + cover），即落在垫底后面，
   所以 0 档看到的是照片的**右半幅**（发丝/衣饰/环境）而不是整张脸；整张脸由左侧圆形头像承担。
4. **color-mix 的机器可读值**：Chrome 的 computed 值是 `color(srgb 1 1 1 / 0.65)`，harness 只按「非透明」判定；
   不支持 color-mix 的浏览器吃 `rgba()` 回退行（同一档不透明度）。
5. `@supports not (filter: blur(4px))` 回退档：照片不再模糊 → 右区抬到 .88/.88（整块回到厚遮罩），
   此时「右侧露照片」不成立（**没有模糊就没有底气露**），文字照样 ≥4.5:1。
6. 本 harness 断言的是 P5.75 遮罩；P5.76 的树上 A/B/C 组的遮罩断言会失败（设计变更，非回归）。
